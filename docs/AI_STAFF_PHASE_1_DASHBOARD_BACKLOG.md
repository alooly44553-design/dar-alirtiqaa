# المرحلة الأولى: لوحة قيادة طاقم الذكاء الاصطناعي — قائمة التنفيذ والقبول

**المشروع:** منظومة دار الإرتقاء الفكري التعليمية فقط  
**الحالة:** خطة تنفيذ مقترحة؛ لم يبدأ تنفيذ التطبيق بهذه الوثيقة  
**النطاق:** مواصفات واجهة ومهام قابلة للتنفيذ والاختبار في بيئة معاينة معزولة  
**قيود ملزمة:** لا تعديل على قاعدة البيانات الحية أو الإنتاج، لا حذف بيانات، لا نشر، لا إرسال رسائل أو إنشاء اجتماعات حقيقية، ولا استخدام أسرار في الواجهة. أي انتقال إلى ذلك يحتاج موافقة إدارية منفصلة.

## 1. هدف المرحلة

إنشاء لوحة قيادة أولية تتيح للإدارة رؤية حالات الوكلاء والمهام والموافقات وسجل النشاط بوضوح، مع فصل ما هو «مخطط» عما هو «منفذ ومتحقق منه». لا تدّعي اللوحة أن الوكلاء يعملون دائمًا أو لحظيًا ما لم يوجد عامل خلفي وتكامل فعلي واختبارات تثبت ذلك.

## 2. نطاق النسخة الأولى

### الشاشة الرئيسية
- ملخص الحالات: وكلاء مُعرّفون، مهام قيد الانتظار، مهام تحتاج موافقة، أخطاء، وآخر تحديث.
- حالة كل مكوّن بعلامة واضحة: غير مهيأ، إعداد تجريبي، يعمل ومتحقق منه، متوقف، أو غير معروف.
- وقت آخر فحص ومصدر الحالة؛ لا تعرض حالة «متصل» بناءً على قيمة ثابتة أو بيانات تجريبية.

### سجل الوكلاء
- تعريف الدور، الوصف، القنوات المصرح بها، الأدوات المسموح بها، حدود الصلاحية، وحالة التشغيل.
- أدوار ابتدائية مقترحة: المنسق، الإداري، التعليمي، الإشراف والجودة، التواصل، التقنية والأمن، والتقارير.
- الأدوار تعريفات تنظيمية فقط؛ لا تُنشأ هويات أو حسابات أو صلاحيات خارجية تلقائيًا.

### قائمة المهام
- الحقول: معرّف، عنوان، الجهة/الدور المسؤول، وقت الإنشاء، الحالة، مستوى الخطورة، مصدر الطلب، وهل تتطلب اعتمادًا بشريًا.
- حالات موحدة: مسودة، بانتظار الاعتماد، معتمدة للتجربة، قيد التنفيذ، مكتملة بعد التحقق، فاشلة، أُلغيت.
- منع تكرار المهمة عند إعادة المحاولة باستخدام معرّف idempotency واضح عند بناء الخلفية.

### صندوق الموافقات
- عرض الطلب، أثره المتوقع، البيانات/القنوات المتأثرة، المخاطر، خطة التراجع، وهوية صاحب الاعتماد ووقته.
- الإجراءات الحساسة والنشر والإرسال الخارجي وتغييرات البيانات محظورة افتراضيًا حتى اعتماد بشري صريح.
- لا يُعد فتح الطلب أو الضغط على زر تجريبي اعتمادًا فعليًا لأي عملية خارجية.

### سجل النشاط والتدقيق
- تسجيل أحداث إنشاء المهمة وتغيير حالتها والاعتماد والرفض والفشل.
- أقل قدر لازم من البيانات؛ لا كلمات مرور أو رموز وصول أو أسرار أو محتوى شخصي غير لازم.
- السجل التجريبي موسوم بوضوح ولا يختلط بسجلات الإنتاج.

## 3. متطلبات الأمان والخصوصية

- مصادقة وصلاحيات على الخادم قبل إتاحة بيانات أو إجراءات إدارية؛ إخفاء الزر وحده ليس حماية.
- مبدأ أقل صلاحية وفصل أدوار المشاهدة والإدارة والاعتماد.
- تحقق من المدخلات، حماية من CSRF/XSS وفق بنية التطبيق، تحديد معدل الطلبات، ورسائل خطأ لا تكشف الأسرار.
- فصل بيانات الاختبار عن بيانات المستفيدين والإنتاج.
- أي تكامل خارجي يبدأ بوضع المعاينة أو المحاكاة، ولا ينتقل إلى التنفيذ الحقيقي إلا بعد موافقة منفصلة واختبار موثق.

## 4. خطة التنفيذ

1. **جرد البنية الحالية:** تحديد إطار التطبيق ومساراته ونمط المصادقة والاختبارات الحالية قبل اختيار مكان اللوحة أو مكتبات جديدة.
2. **نموذج واجهة آمن:** بناء شاشة معاينة باستخدام بيانات تجريبية موسومة؛ لا تُعرض بيانات وهمية على أنها حالة حقيقية.
3. **عقود البيانات:** تعريف مخططات TypeScript/JSON لحالات الوكيل والمهمة والموافقة وسجل التدقيق؛ لا تُنفذ ترحيلات قاعدة بيانات في هذه المرحلة.
4. **اختبارات الواجهة:** حالات التحميل والفراغ والخطأ والصلاحيات والشاشات الصغيرة وإمكانية الوصول.
5. **طبقة API تجريبية:** لا تُضاف إلا بعد مراجعة مسارات الخادم الحالية، مع تحقق صلاحيات الخادم وسجلات تدقيق.
6. **مراجعة أمنية وطلب مراجعة منفصل:** توثيق الملفات المتغيرة والاختبارات الفعلية والقيود المعروفة، ثم طلب اعتماد قبل أي دمج أو نشر يتجاوز الوثائق/المعاينة.

## 5. معايير القبول — لا تُعلّم كمكتملة إلا بعد تنفيذها فعليًا

- [ ] جرد البنية الحالية ومسارات المصادقة موثق بمراجع ملفات فعلية.
- [ ] واجهة لوحة قيادة قابلة للعرض في المعاينة فقط.
- [ ] جميع البيانات التجريبية تحمل تسمية واضحة بأنها تجريبية.
- [ ] لا توجد أزرار تُنفذ إرسالًا خارجيًا أو تغييرات إنتاجية.
- [ ] الحالات المعروضة لا تدّعي تشغيل وكيل أو اتصال قناة بلا دليل من فحص فعلي.
- [ ] اختبارات حالات التحميل والفراغ والخطأ والهواتف والصلاحيات نُفذت وسُجلت نتائجها.
- [ ] لا أسرار أو بيانات حساسة ضمن ملفات الواجهة أو سجلاتها.
- [ ] مراجعة التغييرات والاعتماد الإداري موثقان قبل الدمج أو النشر.

## 6. ما هو خارج المرحلة

- تشغيل دائم للوكلاء أو طابور مهام إنتاجي.
- إرسال رسائل فعلية عبر WhatsApp أو Telegram أو الشبكات الاجتماعية.
- قراءة/كتابة بيانات المستفيدين أو تعديل قاعدة البيانات الحية.
- إنشاء اجتماعات Zoom أو الانضمام إليها تلقائيًا.
- وكيل صوتي يشارك ويتحدث داخل اجتماع Zoom؛ هذه القدرة تظل غير مؤكدة حتى تثبت آلية رسمية مدعومة وتُختبر عمليًا.
- تفعيل فوترة أو اشتراكات أو مزود ذكاء اصطناعي مدفوع.

## 7. قرار مطلوب قبل أي توسيع

بعد معاينة النموذج وتقديم نتائج الاختبارات والتكلفة التقديرية، تختار الإدارة أحد الخيارات:
- **أ — اعتماد الانتقال إلى API تجريبي محمي ومفصول عن الإنتاج.**
- **ب — طلب تعديلات على النموذج أو الصلاحيات.**
- **ج — إيقاف المرحلة دون تغييرات إضافية.**

الافتراضي حتى صدور القرار: لا دمج إنتاجي، ولا نشر، ولا تغييرات قاعدة بيانات أو تكاملات خارجية حقيقية.
