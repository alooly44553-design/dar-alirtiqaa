# منظومة مدارس / مراكز دار الإرتقاء الفكري التعليمية

منصة تعليمية عربية باتجاه كتابة من اليمين إلى اليسار، للتعريف بالبرامج واستقبال طلبات التسجيل والخدمات، مع واجهات الإدارة والتشغيل وبوابات أدوار التعليم.

- الموقع العام: https://alirtiqaa-educational-platform.vercel.app/
- المطوية التعريفية: `brochure.html`
- الحزم والمجالات: `education-packages.html` والصفحات المرتبطة بها
- لوحة الإدارة: `admin.html`
- بوابة العمل المدرسي: `portal.html`
- بوابات الأدوار: `student.html` و`teacher.html` و`parent.html`
- التقارير: `reports.html`
- سياسة الخصوصية: `privacy.html` (مسودة تنتظر الاعتماد)
- شروط الاستخدام: `terms.html` (مسودة تنتظر الاعتماد)
- SEO: `robots.txt` و`sitemap.xml`
- نموذج التشغيل والمرجعية: `OPERATING_MODEL.md`
- القوالب التشغيلية: `operations-templates.html` (36 قالبًا تعليميًا فارغًا)

## إصدار الويب والتطبيق

- رقم الإصدار الموحّد في بيانات الحزمة وPWA وAndroid: **1.1.3**.
- اسم العرض المعتمد في إعدادات التطبيق: **منظومة مدارس ومراكز دار الإرتقاء الفكري التعليمية**.
- معرف Android: `com.daralirtiqaa.app`.
- إعداد Capacitor يشير إلى الموقع المستضاف حتى تستخدم البوابات وواجهات API الأصل نفسه.
- خدمة PWA لها رقم cache مستقل يُحدّث مع إصدارات الويب حتى لا تستمر الأجهزة في استخدام ملفات قديمة.
- توجّه `robots.txt` محركات البحث إلى الصفحات العامة، وتطلب عدم فهرسة صفحات الأدوار والإدارة. هذه تعليمات فهرسة فقط وليست ضابطًا أمنيًا.

## البنية والتكاملات

- الواجهة العامة ونماذج الطلبات: صفحات HTML مستقلة وواجهات API تحت `api/`.
- بيانات كتالوج الخدمات والرسوم وطلبات الخدمات العامة والتسجيل: واجهات التعليم المرتبطة بـ Neon وفق المسارات الحالية.
- وحدات التشغيل المدرسي والمصادقة/الأدوار التي ما زالت مرتبطة بـ Supabase تُدار بصورة منفصلة؛ لا تُلغى أو تُنقل إلى Neon دون اختبار توافق وخطة رجوع.
- Android: Capacitor، مع مهمة بناء عبر GitHub Actions في `.github/workflows/android-apk.yml`.
- المرفقات العامة معطلة مؤقتًا حتى اكتمال التخزين الخاص واختبارات عزل الوصول.
- تكاملات النشر الخارجي والتسويق لا تعتبر فعالة لمجرد وجود واجهاتها؛ يلزم ربط الحسابات والصلاحيات واختبار القنوات وموافقة المسؤول المخوّل.

## البناء والنشر

### الموقع
الدفع إلى الفرع `main` مرتبط بنشر Vercel وفق إعدادات المشروع. بعد كل تغيير، راجع حالة النشر وسجلات البناء، ثم اختبر الصفحات العامة وواجهات API في بيئة مناسبة.

### Android
تقوم GitHub Actions بإنشاء حزمة الويب، وإعداد مشروع Capacitor، وبناء Debug APK عند الدفع إلى `main` أو عند تشغيل Workflow يدويًا. لإعداد بناء محلي لأول مرة:

1. `npm install`
2. جهّز مجلد `www` بنسخ صفحات HTML وملفات `app.webmanifest` و`icon.svg` و`logo.svg` و`sw.js` وملفات `ads/`.
3. نفّذ `npx cap add android` إذا لم يكن مشروع Android موجودًا.
4. نفّذ `npx cap sync android`.
5. من مجلد `android` شغّل `./gradlew assembleDebug`.

نسخة Release لا تُعتمد إلا بعد توفير أسرار التوقيع عبر إعدادات GitHub Secrets والتحقق من توقيع APK وتثبيته وتحديثه. لا تحفظ مفاتيح التوقيع أو كلمات المرور داخل المستودع.

## الحوكمة والضوابط

- القرار الإداري النهائي بيد الإدارة البشرية المخولة، ويجب أن تبقى الموافقات والرفض والإجراءات ذات الأثر موثقة.
- لا تُجرى اختبارات تنشئ بيانات وهمية أو تغيّر سجلات حقيقية في قاعدة الإنتاج.

- لا تُرفع المرفقات ولا تُفعّل المراسلات أو المنشورات الخارجية قبل استكمال ضوابط التخزين والاعتماد.
- سياسات الخصوصية وشروط الاستخدام المرفقة حاليًا مسودتان تشغيليتان، ويجب مراجعتهما واعتمادهما قبل الإعلان عن الإطلاق العام النهائي.

## ربط Zoom — إضافة الإصدار 1.1.2
- صفحة الإدارة المحمية: `zoom-operations.html`.
- API من جهة الخادم: `POST/GET /api/zoom/meetings`، مع تحقق جلسة Supabase Auth ودور الإدارة قبل أي قراءة لإعداد الربط أو إنشاء اجتماع.
- يستخدم المسار Server-to-Server OAuth ويحتاج `ZOOM_ACCOUNT_ID` و`ZOOM_CLIENT_ID` و`ZOOM_CLIENT_SECRET` كأسرار خادمية، و`ZOOM_HOST_USER_ID` كمعرّف أو بريد المستخدم المضيف المرخّص. لا تُضع الأسرار في واجهة المتصفح أو المستودع، ويلزم نطاق إنشاء الاجتماعات الأدنى مثل `meeting:write:meeting:admin`.
- تم فحص متغيرات إنتاج Vercel دون فك تشفير القيم، ولم تظهر متغيرات Zoom المطلوبة. لذا ستعرض صفحة الإدارة «غير مهيأ» ولن تنشئ اجتماعات إلى أن تُضاف بيانات تطبيق Zoom الرسمية إلى Production Environment وتُعاد عملية النشر.
- عند التهيئة، يتيح المدير إنشاء اجتماع بوقت ومنطقة زمنية ومدة يحددها بنفسه، ثم يعرض رابط انضمام المشاركين فقط؛ لا يعيد رابط `start_url` الخاص بالمضيف.
- أنشئنا المسار والواجهة لكن يلزم تشغيل اختبار إنشاء فعلي بعد ضبط بيانات Zoom، والتحقق من إعدادات الحساب والمضيف والصلاحيات. وجود الكود وحده لا يجعل اجتماعات Zoom فعالة.

 
### سجلات اجتماعات Zoom
تتوفر واجهة إدارية في `zoom-operations.html`، ومسار عام متوافق للواجهة `/api/zoom/meetings` يُعاد توجيهه عبر `vercel.json` إلى الوظيفة التعليمية الموجودة، ومنطق Zoom المشترك محفوظ في `lib/zoom-meetings.js` لتجنب تجاوز حد وظائف Vercel Hobby، مع جدول `education.zoom_meetings` عبر migration `database/neon/migrations/20261019_add_zoom_meetings.sql`. لا يحفظ الجدول رابط المضيف المميز أو أسرار OAuth. يعتمد إنشاء الاجتماعات على إعداد Server-to-Server OAuth رسمي في Vercel، وهو غير مهيأ حاليًا لأن مفاتيح Zoom المطلوبة لم تُضف بعد.
