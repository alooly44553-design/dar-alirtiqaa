# مراكز الإرتقاء الفكري الصحية

تطبيق ويب عربي مستقل (RTL/PWA) بصفحات تنظيم الخدمات والمواعيد والطلبات الإدارية والخطط والبرامج والمهام والمناوبات والمخزون والتقارير ومحتوى المركز.

## حدّ التشغيل الحالي

- واجهة التطبيق ونماذجه الأساسية تعمل في المتصفح.
- النماذج الحالية تحفظ البيانات في `localStorage` على الجهاز المستخدم، ولا تتزامن بين الموظفين أو الفروع ولا ترسل الطلبات إلى إدارة المركز.
- توجد قاعدة بيانات صحية مستقلة وجداول تشغيلية أولية، لكن واجهة التطبيق لا تستخدمها بعد لتخزين السجلات اليومية.
- تسجيل دخول الموظفين وصلاحيات الأدوار وعزل الوصول حسب المركز غير مكتملة. لا تدخل أسماء مرضى أو أرقام هويات أو تشخيصات أو ملفات أو أي معلومات صحية حساسة.
- المواعيد التي تحفظها الواجهة المحلية ليست حجوزات مؤكدة، ولا ينبغي الاعتماد عليها لتشغيل خدمة صحية فعلية.
- لا يُعد وجود موقع منشور أو اتصال ناجح بقاعدة البيانات دليلًا على أن التطبيق جاهز للتشغيل الإنتاجي.

## فحص الاتصال

- `GET /api/health/status` فحص تقني غير حساس يتحقق من إمكان وصول نشر هذا التطبيق إلى قاعدة بياناته المخصصة.
- يعيد الفحص حالة اتصال عامة فقط، ولا يعرض بيانات القاعدة أو أي سجل.
- هذا المسار لا يفعّل تسجيل الدخول أو الصلاحيات أو استقبال المواعيد أو مزامنة بيانات النماذج. نجاحه ليس اعتمادًا للإطلاق.

## ملفات التطبيق

- `index.html`: غلاف التطبيق والتنقل.
- `app.js`: الصفحات والنماذج والحفظ المحلي والتصدير.
- `styles.css`: تصميم متجاوب للأجهزة.
- `app.webmanifest` و`sw.js`: تهيئة PWA والملفات الثابتة.
- `privacy.html`: توضيح حدود الخصوصية والاستخدام.
- `api/health/status.js`: فحص اتصال قاعدة البيانات دون إظهار بيانات حساسة.

## قاعدة البيانات المعزولة

توجد جداول مبدئية في مشروع Neon مستقل باسم `dar-alirtiqaa-health`:

- `health_centers`: بيانات الفروع وحالة اعتمادها.
- `health_center_staff`: أعضاء الطاقم والأدوار ومرجع هوية المصادقة.
- `health_center_records`: السجلات الإدارية مصنفة حسب النوع والحالة والفرع.
- `health_center_audit_log`: سجل تدقيق الأحداث.
- جداول أولية للمواعيد والطلبات والمهام والوثائق في مخطط `health`.

حالة التحقق بتاريخ 20 أكتوبر 2026: لم تسجل الجداول بعد فروعًا أو موظفين أو سجلات تشغيلية؛ لم يُفعّل مزود مصادقة، ولم تُنشأ سياسات RLS للقراءة والكتابة، ولا توجد خطة نسخ احتياطي تلقائية مفعلة في إعدادات المشروع. لا تُربط الواجهة بهذه الجداول ولا تستخدم بيانات حقيقية قبل استكمال المصادقة، وسياسات العزل حسب الفرع والدور، وسجل التدقيق، والنسخ الاحتياطي والاستعادة واختبارات الأمان.

## شروط ما قبل الإطلاق الفعلي

1. اعتماد أسماء الفروع وعناوينها وبيانات التواصل والخدمات المصرح بتقديمها لكل فرع.
2. تهيئة حساب مالك موثق وآمن، ثم المصادقة وجلسات المستخدمين واستعادة الحساب وإسناد الأدوار.
3. تنفيذ واجهات خلفية لجميع النماذج المطلوبة، مع التحقق من الهوية والصلاحية والفرع على الخادم في كل طلب.
4. إضافة سياسات قاعدة البيانات المناسبة، وسجل تدقيق لا يتضمن أسرارًا أو بيانات سريرية في التفاصيل.
5. إعداد نسخ احتياطي قابل للتطبيق واختبار استعادة فعلي؛ المشروع الحالي لا يوفّر جدولة النسخ التلقائي عبر الإعداد المستخدم.
6. تحديد قنوات الإشعارات بعد توفير حسابات الإرسال المعتمدة واختبار نجاحها وفشلها.
7. تعبئة بيانات الطاقم والمخزون والمهام من مصادر معتمدة فقط، دون بيانات افتراضية تُعرض كأنها حقيقية.
8. مراجعة الخصوصية والاحتفاظ والموافقات والمتطلبات النظامية المحلية من المسؤول المختص.
9. اختبار الوصول غير المصرح به، وعزل مراكز متعددة، والتحقق من المواعيد والطلبات والتقارير والتصدير، ثم اعتماد الإصدار قبل توسيع النشر العام.

يجب أن يظل التطبيق في وضع الاختبار وألا يستقبل بيانات صحية أو سجلات مرضى حقيقية حتى تُغلق متطلبات الأمان والتشغيل أعلاه.
