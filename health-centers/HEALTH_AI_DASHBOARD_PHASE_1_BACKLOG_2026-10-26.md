# المرحلة الأولى: لوحة قيادة طاقم الذكاء الاصطناعي — المنظومة الصحية

**المشروع:** منظومة الإرتقاء الفكري الصحية فقط  
**الحالة:** خطة توثيقية للمراجعة؛ لا تعني بدء التنفيذ أو تشغيل أي وكيل  
**تاريخ الإعداد:** 26 أكتوبر 2026  
**صاحب الاعتماد النهائي:** علي الأهدل — المدير الإداري، الإرتقاء الفكري الصحية

## 1. الهدف والنطاق

إعداد لوحة قيادة إدارية RTL باللغة العربية لمتابعة تعريفات الوكلاء والمهام والموافقات وسجل التدقيق، مع فصل الحالة المخططة عن الحالة التي ثبت تشغيلها فعليًا. النطاق إداري وتنظيمي غير سريري؛ لا تُدخل بيانات مرضى أو بيانات صحية حساسة حقيقية في هذه المرحلة.

هذه الوثيقة تخص المنظومة الصحية فقط. لا تغيّر ولا تفوّض أي عمل على المنظومة التعليمية أو الحكومية والعامة أو بطاقة الإرتقاء النموذجية أو مشروع واتساب المستقل.

## 2. حدود أمان ملزمة

- لا اتصال بقاعدة الإنتاج، ولا ترحيلات أو حذف بيانات أو تغيير أسرار أو إعدادات نشر.
- لا إرسال حقيقي عبر WhatsApp أو Telegram أو الشبكات الاجتماعية، ولا إنشاء/الانضمام إلى اجتماع Zoom أو تسجيل أو بث صوت فعلي.
- لا تُعرض أي حالة «متصل» أو «يعمل» إلا بوجود فحص حديث موثق ومصدر حالة واضح؛ البيانات التجريبية موسومة بأنها تجريبية.
- كل إجراء حساس، أو نشر، أو إرسال خارجي، أو تغيير بيانات، أو تشغيل اجتماع/تسجيل، يتطلب موافقة بشرية منفصلة وصريحة قبل التنفيذ.
- لا تُسجّل أسرار أو رموز وصول أو محتوى شخصي غير لازم في واجهة المستخدم أو سجلات التدقيق.
- يجب إبقاء استقبال الطلبات والبيانات الحقيقية معطلًا إلى أن تُعتمد الخصوصية وسير العمل وتكتمل الاختبارات اللازمة.

## 3. متطلبات لوحة القيادة المقترحة

### أ. ملخص الحالة
- عدد تعريفات الوكلاء، المهام المنتظرة، طلبات الاعتماد، حالات الفشل، وآخر وقت تحديث.
- حالات موحدة: غير مهيأ، تجريبي، بانتظار اعتماد، يعمل ومتحقق منه، متوقف، فشل، أو غير معروف.
- عرض مصدر الحالة وتوقيتها؛ انتهاء مهلة heartbeat يحوّل الحالة إلى «قديمة/غير معروفة» بدل إبقاء اتصال وهمي.

### ب. سجل الأدوار
- أدوار مقترحة: المدير الإداري الذكي، العمليات والخدمات، الإشراف والجودة، الخصوصية والأمن، الاجتماعات والتكاملات، الاتصالات والقنوات، التقارير والتحليلات، والدعم الفني.
- هذه تعريفات تنظيمية فقط؛ لا تعني إنشاء حسابات أو وكلاء نشطين أو صلاحيات مزود خارجي.

### ج. المهام والموافقات
- حقول المهمة: معرّف فريد، عنوان، مسؤول، وقت الإنشاء، الحالة، مستوى المخاطر، المصدر، وهل تتطلب اعتمادًا بشريًا.
- صندوق الموافقات يعرض الأثر المتوقع، القنوات والبيانات المتأثرة، المخاطر، خطة التراجع، وهوية المعتمد وتوقيت القرار.
- اعتماد واجهة تجريبية لا ينفذ إجراءً خارجيًا. عند بناء الخدمات الخلفية يجب استخدام منع التكرار (idempotency) والتحقق من الصلاحيات على الخادم.

### د. سجل التدقيق
- تسجيل إنشاء المهمة وتغيير الحالة والاعتماد والرفض والفشل، مع أقل قدر لازم من البيانات.
- فصل سجلات الاختبار عن أي سجلات تشغيل حقيقية، ومنع تضمين الأسرار والبيانات الحساسة.

## 4. خطة العمل المرحلية

1. **جرد تقني غير هدّام:** توثيق إطار التطبيق ومسارات الواجهة والمصادقة والصلاحيات والاختبارات الموجودة بالاستناد إلى ملفات فعلية في المستودع.
2. **نموذج واجهة للمعاينة:** بيانات اصطناعية موسومة، بلا اتصال بقاعدة بيانات أو قنوات خارجية.
3. **عقود بيانات:** تعريف مخططات حالات الوكيل والمهمة والموافقة والتدقيق دون إنشاء جداول أو تنفيذ ترحيلات.
4. **اختبارات الواجهة:** التحميل والفراغ والخطأ والصلاحيات والشاشات الصغيرة وإمكانية الوصول، مع تسجيل النتائج الفعلية.
5. **مراجعة أمنية:** مراجعة الصلاحيات على الخادم، التحقق من المدخلات، حماية الجلسات وCSRF/XSS حسب البنية، تحديد المعدل، وعدم كشف الأسرار.
6. **طلب مراجعة منفصل:** تقديم الملفات المتغيرة ونتائج الاختبارات والقيود قبل أي انتقال إلى API تجريبي. لا تمنح هذه الوثيقة موافقة على نشر أو تشغيل خارجي.

## 5. بوابات قبول لا تُعتبر مكتملة دون دليل

- [ ] جرد البنية ومسارات المصادقة والصلاحيات بمراجع ملفات فعلية.
- [ ] واجهة معاينة RTL تعمل في بيئة معزولة.
- [ ] البيانات الاصطناعية معلّمة بوضوح، ولا تختلط ببيانات حقيقية.
- [ ] لا أزرار أو مسارات تنفذ إرسالًا خارجيًا أو تغييرات إنتاجية.
- [ ] لا ادعاء باتصال الوكلاء أو القنوات دون فحص موثق وحديث.
- [ ] اختبارات التحميل والفراغ والخطأ والصلاحيات والجوال وإمكانية الوصول نُفذت وسُجلت.
- [ ] مراجعة أمنية وسجل تغييرات مكتملان قبل اعتماد أي API تجريبي.
- [ ] لا أسرار أو بيانات مستفيدين حقيقية في الواجهة أو ملفات الاختبار أو السجلات.

## 6. قيد الاستضافة السعودية

قرار الإدارة هو استضافة البيانات داخل المملكة العربية السعودية فقط. الفحص السابق أظهر أن مشروع Neon الصحي الحالي في سنغافورة، ولم تعرض قائمة المناطق التي فُحصت منطقة سعودية. لذلك لا يجوز وصف القاعدة الحالية بأنها مستضافة في السعودية، ولا إنشاء/نقل قاعدة أو اختيار دولة بديلة تلقائيًا.

قبل أي تصميم متصل بالبيانات، يجب إثبات مواقع قاعدة البيانات والنسخ الاحتياطية والسجلات والخدمات التابعة من وثائق المزود وإعداداته الفعلية. إذا لم يتوفر مزود مناسب داخل السعودية، يتوقف المسار ويُطلب قرار إداري جديد.

## 7. ما هو خارج المرحلة

- تشغيل دائم أو ذاتي للوكلاء أو طابور مهام إنتاجي.
- استقبال بيانات مرضى أو معلومات صحية حساسة، أو تشغيل استقبال الطلبات الحقيقية.
- إرسال رسائل أو إنشاء اجتماعات أو تسجيلات أو مشاركة صوتية فعلية.
- ترحيل أو إنشاء أو تعديل قاعدة بيانات، أو نشر إنتاجي.
- إثبات مشاركة صوت AI داخل Zoom؛ استقبال RTMS وحده لا يثبت أن المشارك الآلي يستطيع إرسال صوت إلى الاجتماع.
- أي تعديل على مشروع آخر ضمن عائلة الإرتقاء الفكري.

## 8. القرار المطلوب من الإدارة

بعد مراجعة الخطة، يُرجى اختيار أحد الخيارات:

- **أ — الموافقة على إعداد نموذج واجهة معاينة معزول فقط، بلا API أو بيانات حقيقية.**
- **ب — طلب تعديل الخطة قبل بدء النموذج.**
- **ج — إيقاف المرحلة حاليًا.**

**الافتراضي حتى صدور القرار:** لا تنفيذ تطبيقي أو تكامل خارجي أو اتصال قاعدة بيانات أو نشر. أي انتقال لاحق إلى API تجريبي يحتاج مراجعة منفصلة بنتائج النموذج والاختبارات.
